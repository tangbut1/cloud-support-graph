## 1. 这个项目到底是干什么的

### 1.1 一句话

**给云服务器用户做的"智能客服 + 工单系统"**：用户报故障 → AI 先查知识库、再查你的服务器状态 → 能直接回答就回答，需要人工动手就转给坐席，坐席一键批准后系统自动建工单。

### 1.2 一个具体的故事（我们的种子数据就是照这个设计的）

> 张三买了台阿里云服务器 `ubuntu-web-prod`，今天网站打不开了，浏览器显示 **502 Bad Gateway**。
>
> **没有这个系统时**：张三去提工单 → 客服先问"您用的什么系统""报什么错""端口放行了吗" → 来回五六轮 → 客服手工查后台 → 半小时过去。
>
> **有这个系统时**：
> 1. 张三登录，输入"网站打不开了，报 502"（还能传一张报错截图）；
> 2. AI 判断这是"故障排查"意图 → 调工具查张三**自己名下**的 `ubuntu-web-prod`；
> 3. 工具返回：`nginx` 在跑，但 `backend-8080` 是 `stopped`，防火墙端口列表里**没有 8080**，而且 Swap 是 0（小内存容易 OOM）；
> 4. AI 基于**真实数据**给出结论："后端进程已停止，且 8080 端口未在防火墙放行，建议先启动进程再放行端口"；
> 5. 因为"改防火墙"属于高危操作，AI **不自己动手**，而是整理好交接摘要 + 工单草稿，把流程**挂起**；
> 6. 坐席王工登录看到待接管队列，一眼看完摘要，点"批准建单并回复"；
> 7. 流程**从挂起点恢复**，工单落库，张三收到回复。

这个故事里的每一步，都对应项目里的一个模块。

### 1.3 三个技术亮点（这就是答辩拿分点）

| 亮点 | 解决什么问题 | 用到的技术 |
|---|---|---|
| **不让大模型瞎编** | 模型不懂云厂商收费/赔付政策时容易胡说 | 知识库检索 + 分数阈值：低于阈值**直接拒答**，不自由发挥 |
| **不让大模型越权** | 用户诱导模型"帮我查隔壁李四的服务器" | 身份只在服务端从 JWT 取，工具参数里**根本没有** user_id 可填 |
| **人机协同可恢复** | AI 判断要人工介入时，流程不能丢 | LangGraph 的 `interrupt()` 把状态存盘，坐席批准后 `Command(resume=...)` 接着跑 |

### 1.4 为什么这门课值得做

它不是"增删改查管理系统"（题目池里 90% 是那种），而是**有真实业务闭环 + 安全边界 + 量化评测**的系统。报告第 5 章能写出实验数据（意图准确率、拒答率、越权拦截率），面试也能讲深。

## 2. 系统分几层，你写的代码在哪一层

### 2.1 用餐厅打比方

| 餐厅 | 我们项目 | 干什么 |
|---|---|---|
| 顾客看的菜单、餐桌 | **前端 React** | 展示界面、收集用户输入 |
| 门童 / 领位 | **Nginx** | 静态页直接给，/api 请求转后厨 |
| 服务员 | **FastAPI 路由** | 接收请求、核对身份、传到对应部门 |
| 后厨各工位 | **services 业务逻辑** | 状态机、检索、规则判断（**确定性代码**） |
| 主厨做决策 | **LangGraph** | 先判断意图 → 决定走哪条流程 → 要不要请示老板 |
| 专用设备接口 | **MCP 工具** | 查库存、查设备（只能查"你那桌"的） |

| 整店打包成集装箱 | **Docker** | 保证在哪都能原样开业 |

### 2.2 你现在站在哪一层

**第 1 层（数据层）的地基**。你写的 `database.py` 决定了"账本有哪些栏目、每栏存什么、什么数据算非法"。

> 为什么必须你亲手写？因为上层所有代码都建立在这些表上：Day 2 的登录要查 `users`，Day 3 的检索要查 `kb_chunks`，Day 5 建工单要写 `tickets`。**表写错，上面全崩**。而且第 5 章面试必问"你的数据库怎么设计的"。

### 2.3 一次真实请求的数据流（把图串起来）

```text
张三在网页输入"网站打不开"
  → 前端发 POST /api/conversations/{id}/chat/stream
  → Nginx 看到 /api 开头，转给后端 8000
  → FastAPI 路由收到，先用 JWT 解析出"这是张三（id=1）"
  → LangGraph 开始跑：判断意图=故障排查
  → 调 MCP 工具 diagnose_instance_network(instance_id=1)

  → 回复通过 SSE 一个字一个字推回浏览器
```

**这条链路上，你现在写的表会被查询 3 次**：身份、实例、追踪记录。

- **和谁连接**：被几乎所有模块 import；读仓库根目录 `.env`。

### 3.2 `backend/app/main.py`（我已写好）
- **是什么**：FastAPI 应用的入口。启动时做的事写在这里。
- **有什么用**：启动时调用 `init_db()` 自动建库；提供 `GET /api/health` 健康检查。
- **和谁连接**：被 uvicorn 启动；被 Nginx 反代；调用 `database.init_db`。
- **哪一层**：第 2 层（应用层）的大门。

### 3.3 `backend/app/db/database.py` ★你在写
- **是什么**：数据库的"建库脚本 + 连接工厂"。
- **有什么用**：① 告诉 SQLite "要建哪些表、每张表有哪些列和规矩"；② 提供一个统一配置好的连接（开 WAL、开外键、锁等待 5 秒）。
- **和谁连接**：被 `main.py` 启动时调用；被 `seed.py` 调用；Day 2 之后被所有需要读写数据库的模块调用。

### 3.4 `backend/app/db/seed_data.py` / `seed.py` ★你在写 seed()
- **是什么**：演示数据。前者是数据清单（我写好了），后者是把数据写进库的脚本（你写）。
- **有什么用**：让系统一启动就有"张三、李四、5 台云服务器"可以演示，不用手工录。

## 4. "数据层"到底怎么写（你现在唯一要动手的）

### 4.1 三句话

1. 一张表 = 一条 `CREATE TABLE` 语句；
2. 每列 = 列名 + 类型（INTEGER/TEXT/REAL）+ 约束（必填、唯一、只能取某几个值、默认值）；
3. 12 张表 = 12 条语句，中间用分号隔开。

### 4.2 一条语句的解剖（照这个抄格式）

```sql
CREATE TABLE IF NOT EXISTS users (              ← 表名；IF NOT EXISTS = 已存在就跳过（幂等）
    id            INTEGER PRIMARY KEY AUTOINCREMENT,  ← 列名 + 类型 + "自增主键"
    username      TEXT    NOT NULL UNIQUE,             ← 文本 + 必填 + 不许重复
    role          TEXT    NOT NULL CHECK (role IN ('customer','agent','admin')),
                                                 ↑ 必填 + 只能是这三个值之一
    created_at    TEXT    NOT NULL DEFAULT (datetime('now'))
);                                              ← 括号 + 分号，缺一不可
```

### 4.3 12 张表分别是什么（业务含义）

| 表 | 存什么 | 谁用 |
|---|---|---|
| users | 用户（客户/坐席/管理员） | 登录 |
| cloud_instances | 仿真云服务器台账 | 故障诊断 |
| kb_documents / kb_chunks / kb_chunks_fts | 知识库原文、切片、全文索引 | 智能问答检索 |
| conversations | 一次咨询会话 | 聊天 |
| messages | 会话里的每条消息 | 聊天记录 |
| tickets / ticket_events | 工单 + 状态变更审计 | 工单流转 |
| agent_traces | 每轮 AI 的耗时/Token/决策 | 观测看板 |
| eval_runs / eval_case_results | 32 题黄金集跑批结果 | 第 5 章实验 |

## 5. Docker 从零讲

### 5.1 为什么需要它（先讲痛点）

你在本机能跑，因为本机有 Python 3.12、装了一堆依赖包、Windows 上有各种系统库。
把代码拷到阿里云服务器（Ubuntu 24.04）上，**大概率跑不起来**：Python 版本不同、某个包少了系统库、路径不一样……
这叫"**在我电脑上明明是好的**"，是软件行业最经典的坑。

### 5.2 核心概念：集装箱

Docker 把"你的代码 + Python 解释器 + 所有依赖 + 系统库 + 启动命令"**一起打包**成一个箱子。
箱子在 Windows 上能跑，在 Ubuntu 服务器上也能跑，因为箱子自带它需要的一切。

| 概念 | 大白话 | 我们的例子 |
|---|---|---|
| **镜像 image** | 造箱子的**模具/蓝图**（只读） | `cloud-support-graph-backend:latest`，485 MB |
| **容器 container** | 用模具造出来的**正在跑的箱子** | `csg-backend`，运行时内存 39 MB |
| **Dockerfile** | 造箱子的**配方**（一行一条指令） | `backend/Dockerfile` |
| **docker compose** | **箱子管理员**，一次管多个箱子 | `docker-compose.yml` 管后端 + Nginx |
| **数据卷 volume** | 挂在箱子外面的**仓库**，箱子删了数据还在 | `./data:/app/data` → 数据库文件在宿主机 |
| **端口映射** | 箱子内部端口 ↔ 宿主机端口 | `127.0.0.1:8000->8000` |
| **镜像源 mirror** | 国际仓库太慢，用**国内中转仓** | 我们配了 3 个（daocloud / 1ms / rat.dev） |

### 5.3 我们的 Dockerfile 逐行（这就是"配方"）

```dockerfile
FROM python:3.12-slim            # ① 拿一个装好 Python 3.12 的精简 Linux 当底子
ENV PYTHONDONTWRITEBYTECODE=1     PYTHONUNBUFFERED=1     PIP_NO_CACHE_DIR=1           # ② 三个环境变量：不生成缓存文件、日志立刻输出、pip 不存缓存（省体积）
WORKDIR /app                     # ③ 进箱子后默认在 /app 目录
COPY pyproject.toml ./           # ④ 先只拷依赖清单 —— 为了利用 Docker 层缓存
COPY app ./app                   # ⑤ 再拷源码
RUN pip install --upgrade pip setuptools wheel && pip install .
                                 # ⑥ 装依赖（这一步最慢，131 秒）
RUN mkdir -p /app/data           # ⑦ 准备数据目录（运行时会挂载宿主机目录覆盖它）
EXPOSE 8000                      # ⑧ 声明箱子内部用 8000 端口
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000", "--workers", "1"]
                                 # ⑨ 箱子启动时执行的命令
```

> 为什么④⑤要分开？因为 Docker 有"层缓存"：依赖没变时，改代码后重建**不会重新装依赖**，几秒就好。这是工程实践，面试会问。

### 5.4 我们的 docker-compose.yml 逐段

```yaml
services:
  backend:                       # 箱子1：后端
    build: {context: ./backend}  #   用 backend/Dockerfile 现做
    env_file: [./.env]           #   把 .env 配置喂进去（API Key 等）
    environment:                 #   容器内路径覆盖（容器里没有 ../ 这种相对路径）
      APP_DB_PATH: /app/data/app.db
    volumes: [./data:/app/data]  #   ★ 宿主机 data 目录 ↔ 容器 /app/data，数据不丢
    ports: ["127.0.0.1:8000:8000"] # 只映射到本机，开发机不暴露公网
    mem_limit: 700m              #   内存上限（配合 2C2G 服务器）
    restart: unless-stopped      #   崩了自动重启
    healthcheck: ...             #   每 30 秒敲一次 /api/health，判断"活着吗"

  nginx:                         # 箱子2：门童
    profiles: ["full"]           #   前端做好了才启用，现在先不启动
    ports: ["80:80"]
    volumes: [./deploy/nginx.conf:/etc/nginx/conf.d/default.conf:ro]
```

### 5.5 常用命令（背这 6 条就够）

| 命令 | 干什么 | 类比 |
|---|---|---|
| `docker compose build` | 按配方造箱子（改代码后要重跑） | 造集装箱 |
| `docker compose up -d` | 启动所有箱子（后台） | 把箱子放上船 |
| `docker compose ps` | 看箱子状态 | 查船单 |
| `docker compose logs -f backend` | 实时看后端日志 | 看监控 |
| `docker compose down` | 停掉并删除箱子（镜像保留） | 卸货 |
| `docker compose exec backend bash` | 钻进箱子内部 | 进集装箱检查 |

### 5.7 踩过的三个坑（也是报告素材）

1. **代理失效**：系统代理 `127.0.0.1:7897` 在 WSL2 里指向 WSL 自己 → Docker 用不上 → 改用国内镜像源。
2. **IPv6 优先**：Docker Hub 解析到 IPv6 地址，直连超时 → 镜像源走 IPv4 正常。
3. **`# syntax=docker/dockerfile:1`**：这行会让 Docker 额外去 Docker Hub 拉一个元镜像 → 本项目不需要 → 删掉少一个故障点。

## 7. 术语表（遇到不认识的回来查）

| 术语 | 大白话 |
|---|---|
| API | 程序之间的"点菜窗口"，前端按规定格式向后端要数据 |
| 路由 router | 一个 URL 对应一个处理函数 |
| 数据库表 | Excel 的一张 sheet |
| 主键 | 每行的唯一身份证号 |
| 外键 | "这行的值必须存在于另一张表里"的约束 |
| ORM | 用 Python 对象操作数据库的库（我们**不用**，直接写 SQL，更好懂也更好讲） |
| SSE | 服务器一个字一个字往回推（打字机效果），比等全文生成完再返回体验好 |
| JWT | 一个加密的"身份牌"，登录后发给前端，之后每次请求带上 |
| RBAC | 按角色授权：客户/坐席/管理员各能干什么 |
| MCP | 一套"标准工具接口协议"，让模型用统一方式调工具 |
| RAG | 先检索资料再让模型基于资料回答，防瞎编 |
| 镜像 / 容器 | 模具 / 用模具造出来的实例 |
| 幂等 | 同一个操作执行 1 次和 100 次，结果一样 |
